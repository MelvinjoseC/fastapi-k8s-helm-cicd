# Task API — Kubernetes & DevOps Portfolio Project

![CI](https://github.com/MelvinjoseC/fastapi-k8s-helm-cicd/actions/workflows/ci.yml/badge.svg)
![Python](https://img.shields.io/badge/python-3.12-blue)
![License](https://img.shields.io/badge/license-MIT-green)

A small Task Management REST API used to demonstrate an end-to-end
DevOps workflow: a Python/FastAPI service, containerized with a
hardened multi-stage Dockerfile, deployed to Kubernetes with both
**Kustomize** and **Helm**, scaled with an HPA, monitored with
Prometheus/Grafana, and shipped through a GitHub Actions CI/CD pipeline
that includes a real `kind`-cluster smoke deploy.

The goal of this repo is to be small enough to read end-to-end in
twenty minutes, while touching every piece of the toolchain a
DevOps/platform engineer is expected to know.

## Architecture

```
Client → Ingress (TLS) → Service → [Pod, Pod, Pod...] (HPA: 2-10) → Postgres (StatefulSet)
                                                       ↘ Redis (best-effort cache)
```

See [`docs/architecture.md`](docs/architecture.md) for the full diagram
and the reasoning behind each design decision (probe design, network
policy, cache degradation strategy, etc.) — that doc is written to be
talked through in an interview.

## Tech stack

| Layer | Tooling |
|---|---|
| API | Python 3.12, FastAPI, SQLAlchemy, Pydantic |
| Data | PostgreSQL (StatefulSet/managed DB), Redis (cache) |
| Container | Docker (multi-stage, non-root, healthcheck) |
| Orchestration | Kubernetes (Deployment, HPA, PDB, NetworkPolicy, Ingress) |
| Config management | Kustomize (base + dev/prod overlays) **and** a Helm chart |
| CI/CD | GitHub Actions (lint → test → build → Trivy scan → kind smoke test → push → deploy) |
| Observability | Prometheus metrics, ServiceMonitor, alerting rules, Grafana dashboard |
| Testing | Pytest, 12 unit/integration tests, isolated in-memory DB |

## Project structure

```
app/                  FastAPI service, tests, Dockerfile
docker-compose.yml    Local dev stack (api + postgres + redis)
k8s/base/             Raw Kubernetes manifests
k8s/overlays/dev/     Kustomize overlay - 1 replica, debug logging
k8s/overlays/prod/    Kustomize overlay - 5 replicas, larger storage
helm/taskapi/         Equivalent Helm chart (used by the CD pipeline)
monitoring/           ServiceMonitor, PrometheusRule alerts, Grafana dashboard
.github/workflows/    CI (test/build/scan/smoke-deploy) and CD (Helm deploy) pipelines
docs/architecture.md  Design rationale, written for interview walkthroughs
```

## Quick start — local development

```bash
git clone https://github.com/MelvinjoseC/fastapi-k8s-helm-cicd.git
cd taskapi-k8s
docker compose up --build
```

```bash
curl -X POST localhost:8000/tasks -H "Content-Type: application/json" \
  -d '{"title": "Try this API", "description": "It works"}'
curl localhost:8000/tasks
```

API docs (auto-generated by FastAPI) are at `http://localhost:8000/docs`.

### Running tests

```bash
make install
make test
```

12 tests cover CRUD behavior, validation errors, 404s, the cache filter
path, and the health/readiness/metrics endpoints — all running against
an isolated in-memory SQLite DB, so no external services are required.

## Deploying to Kubernetes

### Option A — kind (fastest way to see it running)

```bash
kind create cluster --name taskapi-dev
docker build -t taskapi:dev ./app
kind load docker-image taskapi:dev --name taskapi-dev

cd k8s/overlays/dev
kustomize edit set image ghcr.io/MelvinjoseC/fastapi-k8s-helm-cicd=taskapi:dev
kubectl apply -k .

kubectl rollout status deployment/taskapi -n taskapi-dev
kubectl port-forward svc/taskapi 8080:80 -n taskapi-dev
curl localhost:8080/health
```

### Option B — Kustomize against a real cluster

```bash
kubectl apply -k k8s/overlays/prod
```

### Option C — Helm

```bash
helm upgrade --install taskapi ./helm/taskapi \
  --namespace taskapi --create-namespace \
  -f helm/taskapi/values-prod.yaml
```

> Both `k8s/base/secret.yaml` and the Helm secret template ship with
> **placeholder credentials only**. They exist so the project runs
> out-of-the-box for a demo or CI smoke test. For a real cluster, swap
> these for [Sealed Secrets](https://github.com/bitnami-labs/sealed-secrets)
> or [External Secrets Operator](https://external-secrets.io/) — see the
> comments at the top of `secret.yaml`.

## CI/CD pipeline

`.github/workflows/ci.yml` runs on every push/PR:

1. **Lint** - flake8 + black
2. **Test** - pytest, plus a live smoke test of the running server
3. **Build & scan** - multi-stage Docker build, Trivy vulnerability scan, push to GHCR on `main`
4. **kind smoke deploy** - spins up a real Kubernetes cluster in the CI runner, applies the dev Kustomize overlay, waits for rollout, and curls `/health` through the actual Service — this is the step that catches "works on my machine but the manifests are broken" bugs before merge

`.github/workflows/cd.yml` runs on a version tag (`v1.2.0`) and does a
`helm upgrade` against a production cluster, with automatic `helm
rollback` on failure.

## Observability

- `/metrics` exposes Prometheus-format metrics (request rate, latency
  histograms, in-flight requests) via `prometheus-fastapi-instrumentator`
- `monitoring/servicemonitor.yaml` wires that endpoint into a Prometheus
  Operator install
- `monitoring/prometheus-rules.yaml` defines alerts for error rate, p95
  latency, crash-looping pods, zero-availability, and a maxed-out HPA
- `monitoring/grafana-dashboard.json` is a ready-to-import dashboard
  covering all of the above plus per-pod CPU/memory

## Resilience features worth pointing out in an interview

- Liveness, readiness, and startup probes are split with distinct logic
  (see `docs/architecture.md` for why)
- Redis cache failures degrade gracefully instead of causing 500s
- `maxUnavailable: 0` rolling updates - zero-downtime deploys
- `PodDisruptionBudget` protects against voluntary disruption (node
  drains, cluster upgrades) taking out all replicas at once
- Default-deny `NetworkPolicy` - the API can only reach Postgres, Redis,
  DNS, and the ingress controller
- HPA with separate scale-up/scale-down behavior to avoid flapping
